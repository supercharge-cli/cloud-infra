# Chat channels

Vectra Cloud sandboxes talk over **Telegram**, **Discord**, and/or **Slack**. Use any one channel, or several at once.

## Setup

1. Open your instance on the [dashboard](/dashboard).
2. Under **AI + chat channels**, paste tokens for the channels you want (leave others blank).
3. Click **Save & restart**.

| Channel | What you need |
| --- | --- |
| **Telegram** | Bot token from [@BotFather](https://t.me/BotFather) |
| **Discord** | Bot token + **Message Content Intent** enabled in the Discord developer portal |
| **Slack** | Bot token (`xoxb-…`) **and** app token (`xapp-…`, Socket Mode) |

You also need an AI API key (OpenAI-compatible or Anthropic).

## Pairing (default)

By default only approved users can chat.

1. Message the bot on any configured channel — it replies with a **pairing code**.
2. Dashboard → that instance → **Channel pairing**.
3. Click the pending code (or paste it) → **Approve**.

Use **Refresh** if the code is not listed yet (agent may still be starting).

## Open access

If you enable **Allow all users on every channel** when saving config, anyone who finds the bot can message it. Prefer pairing for private use.

## After the sandbox pauses

Idle sandboxes pause to save cost (see [Pause & resume](/docs/pause-resume)).

| Channel | Wake behavior |
| --- | --- |
| **Telegram** | A DM can auto-wake when the host webhook is armed (`PUBLIC_BASE_URL` set on the site). You may need to **send the message again** after thaw. |
| **Discord / Slack** | Open the dashboard and click **Wake / resume**, then message again. |

## If the bot is silent

1. Check instance status on the [dashboard](/dashboard) — **paused** needs wake; **error** needs logs.
2. Use **View logs** (daemon source) after wake.
3. **Save & restart** after changing tokens or the API key.
4. Confirm pairing is approved (or open access is intentional).

Channel tokens and pairing state live **inside the sandbox**. Destroying the instance removes them; pause does not.
